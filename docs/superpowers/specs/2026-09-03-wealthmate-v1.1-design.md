# WealthMate V1.1 体验与功能增强设计

## 目标

在不破坏 V1 账本、离线缓存、服务器同步和备份能力的前提下，完成一次客户端体验增强：降低页面重建造成的卡顿；首页只保留“快捷记”和“记一笔”；支持用户管理分类和账户名称；账目可查看详情；预算可编辑并在 80%/100% 阈值提醒；统计支持本日、本周、本月折线图、柱状图和饼状图；财富账户可进入详情编辑；汇率可获取、手动录入并显示来源和时间。

## 范围约束

- 保留 Flutter + Drift/SQLite + FastAPI + PostgreSQL + Docker Compose 架构。
- 默认展示币种仍为 CNY。
- 基金/投资账户只记录总额，不增加持仓、行情、买卖或投资建议。
- 所有核心数字由程序计算，AI 只负责草稿解释和月度文字分析。
- 外币没有可靠汇率时显示“待补充汇率”，不猜测。
- 历史月度资产快照不可因后续汇率更新而改写。
- 账目必须继续通过 `client_op_id` 幂等同步，预算、分类、账户修改也必须可跨设备同步。
- V1.1 继续支持断网记账，网络恢复后自动上传并去重。

## 当前问题证据

- `FinanceStore` 是全局 `ChangeNotifier`，一次变更会触发多个页面重建；移动端 `IndexedStack` 同时保留多个页面。
- 首页、账本页和 `AppShell` 都提供记账入口，用户感知为重复入口。
- 客户端分类只有读取，没有用户分类管理界面；服务端分类也只有 `GET /categories`。
- 服务端已有账户 `PATCH /accounts/{account_id}`，但客户端没有账户编辑流程。
- 最近账目是不可点击的列表项，账目模型只有日期，没有完整发生时间。
- 客户端预算页面只有新增逻辑；服务端 `GET /budgets` 当前固定返回空列表，预算不能成为共享账本的一部分。
- 统计页目前只显示月度现金流折线和分类金额列表，没有周期切换、柱状图或饼图。
- 服务端已有汇率读写接口，但客户端没有汇率管理页面和完整的获取/保存流程。

## 产品设计

### 1. 客户端性能和视觉层

将页面状态拆成可局部监听的区域：概览指标、最近账目、统计图表、账户列表和同步状态分别刷新。页面容器不再因单笔账目变化而重建所有页面；移动端页面按首次访问加载并缓存已访问页面。

账目列表使用懒加载；图表放在独立重绘边界；统计结果按周期和状态版本缓存；网络请求不在界面线程执行。使用统一的间距、字体层级、卡片圆角、主色和错误/提醒色。动画只用于页面切换、确认和提醒，时长控制在 150–220ms。

### 2. 首页

首页结构固定为：净资产摘要、两个记账入口、最近账目、本月摘要。首页只出现两个操作：

- `快捷记`：文字/语音输入，自然语言解析后展示草稿，用户确认后入账。
- `记一笔`：打开手动记账表单。

移除首页重复按钮和首页悬浮记账按钮。账本页可保留一个页面级新增按钮，不与首页入口混用。

### 3. 分类管理

新增分类管理页，支持新增、重命名、归档和恢复。分类包含名称、收支类型、排序和启用状态。已被账目引用的分类不能物理删除；归档后历史账目仍保留，新增账目不再显示该分类。分类 ID 保持稳定，名称修改后历史记录可显示新名称。

### 4. 账户和基金账户

财富页的账户卡片变为可点击项，进入账户详情。详情页支持修改账户名称、账户用途、资产/负债类型、币种、初始余额、是否计入流动资产、是否作为默认支付账户和归档状态，并显示账户关联账目。

账户增加 `account_kind`：`cash`、`bank_card`、`wechat`、`alipay`、`foreign`、`fund_investment`、`credit_card`、`loan`、`other`。`fund_investment` 只展示和维护基金/投资账户总额，不管理持仓。

当前余额继续由初始余额和账目计算。用户纠正余额时创建“余额调整”账目，不直接覆盖计算值。

### 5. 账目详情和时间范围

新增账目详情页，显示发生时间、收支类型、原始金额、CNY 折算金额、分类、账户/支付平台、备注、汇率来源和同步状态，并提供编辑、删除和复制操作。

账目新增 `occurred_at` 完整时间字段；旧账目只有日期时按当天 00:00 保存，并在详情中显示“具体时间未记录”。统计周期使用 `occurred_at`，自然语言记账默认使用设备当前时间。

### 6. 预算、调整和提醒

预算变为服务器正式数据，字段包括 ID、月份、分类、金额上限、启用状态、更新时间和服务器版本。客户端支持新增、编辑金额、编辑分类、编辑月份、复制上月预算和归档。

预算使用率达到 80% 时显示黄色提醒，达到 100% 时显示红色提醒，超过 100% 时显示超支提醒。提醒按预算、月份和阈值去重，避免重复通知。V1.1 在打开应用、手动同步和账目入账后检查提醒，并使用应用内提示和系统本地通知；不引入远程推送服务。

### 7. 统计图表

统计页增加周期切换：本日、本周、本月、自定义时间段。

- 折线图：本日按小时，本周按日，本月按日显示支出变化。
- 柱状图：按分类汇总支出，按金额降序显示，手机端最多显示前 6 类并合并“其他”。
- 饼图：显示选定周期内各分类支出占比。
- 摘要卡：总支出、日均支出、最高支出分类、最高支出账户、与上一周期变化。

后端统计结果和客户端离线统计使用同一套字段：`period_start`、`period_end`、`expense_total`、`expense_by_category`、`expense_by_account`、`expense_series`、`income_total`、`net_worth_change`。图表只消费结构化数字，不调用 AI。

### 8. 汇率管理

财富页增加汇率管理区域，列出实际使用的非 CNY 币种。每个币种提供“获取汇率”和“手动录入”操作，显示汇率、日期、来源、最后更新时间和状态。服务器通过可替换的汇率服务获取 Frankfurter 数据，保存汇率快照；客户端保存当前状态并在同步后刷新账户折算金额。

当前资产使用最新可靠汇率；已保存的交易和历史月报继续保留当时的汇率快照。汇率请求失败不影响 CNY 记账和离线工作。

## 数据和接口变化

- `Account`：增加 `account_kind`；保留既有 `is_liquid`、`is_default_payment` 和汇率字段。
- `FinanceTransaction`：增加 `occurred_at`，保留既有 `date` 作为日维度兼容字段。
- `Category`：增加用户可管理的创建、更新、归档接口。
- `Budget`：新增服务器模型、共享查询、创建、更新和归档接口，并接入同步版本。
- `GET /stats`：增加周期参数和分类、账户、时间序列聚合字段。
- 客户端 `ApiClient`：增加分类 CRUD、预算 CRUD、账户更新和汇率管理调用。
- 客户端 `FinanceStore`：增加账户更新、分类管理、预算编辑、汇率刷新和提醒去重状态。
- Drift 数据库：增加相应字段和 schema migration；旧记录按兼容规则填充。

## 测试和验收

- 单元测试覆盖分类新增/重命名/归档、账户编辑、基金账户、余额调整、预算 80%/100%/超支、提醒去重、周期统计和图表聚合。
- API 测试覆盖分类 CRUD、预算 CRUD、账户 PATCH、统计周期、汇率保存和同步幂等。
- Flutter 测试覆盖首页仅两个入口、最近账目详情入口、账户详情编辑、预算编辑、周期切换和离线队列。
- 使用 `flutter analyze`、`flutter test`、后端 `python -m unittest discover -s tests -v` 验证。
- 重新构建 Android APK 和 Windows 客户端。
- 真实验收：手机和电脑登录同一账号；新增/修改分类和账户后双端一致；预算到 80% 和 100% 出现提醒；本日/本周/本月图表数字与账本一致；外币获取汇率后显示来源和更新时间；断网记账恢复网络后只出现一笔。

## 不在本次范围

- 股票、基金持仓、行情和交易。
- 银行或支付平台自动拉账。
- 家庭共享和多用户协作。
- 远程推送平台、短信和邮件提醒。
- 多语言和每日实时汇率。
