## PostgreSQL gate

The committed regression harness covers concurrent pushes, strict per-user versions, locked `User` freshness after identity-map staleness, replay idempotency, and rollback. The required real-PostgreSQL execution could not be performed on this host:

- no `WEALTHMATE_POSTGRES_TEST_DATABASE_URL` was configured;
- Docker CLI was installed, but the Linux daemon was unavailable at `dockerDesktopLinuxEngine`;
- no production database or live-user rows were accessed.

Therefore the required “old implementation fails on real PostgreSQL, repaired implementation passes” evidence remains **NOT VERIFIED**.

The backend full-suite rerun used a controlled workspace temporary directory. Its six failures were test-isolation/order failures in the long-lived `test_api` database fixture (pre-existing rows were visible to tests that expect an empty fixture), not PostgreSQL concurrency evidence. The full suite therefore remains **NOT VERIFIED**.

## Android build diagnosis

The first clean build reproduced two independent failures:

- Kotlin incremental cache registration failed while closing caches for several Flutter plugins. The project-level `kotlin.incremental=false` setting removes that host-toolchain failure without changing application or synchronization behavior.
- The default `cronetHttpNoPlay=false` dependency path pulled Play Services Cronet `141.7340.3`, which AGP 9.1 rejected because `org.chromium.net` was declared by both `cronet-api` and `cronet-shared`. The guarded release path already requires `cronetHttpNoPlay=true`; the successful APK contains `libcronet.143.0.7445.0.so` for all three packaged ABIs.

The release guard initially failed to inspect the APK because the host did not expose `JAVA_HOME` to `apkanalyzer.bat`. The inspector now resolves the installed Android Studio JBR locally and the same guarded build passes without a manually exported Java environment.
